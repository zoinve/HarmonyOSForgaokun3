# Commercial 044 candidate

This is a new candidate, not a repeat of completed boot 043. Desktop acceptance
remains pending. The normal original account/Ability Manager/SceneBoard launch,
graphics provider, authentication, sandbox and service code remain unchanged.
The target/outer bounds remain 150/270 seconds.

The actual original CommitTransaction parcel starts with int32 zero and version,
while RegisterApplicationAgent begins with a remote object. Neither carries the
interface token required by the 043 filter. 044 additionally recognizes code
0/17 on process/fd/handle combinations previously observed with the exact
RenderServiceConnection descriptor. Those records use interface=3, explicitly
an association rather than a new descriptor match. The bounded atomic table
does not transfer matches across forks. It cannot exclude fd/handle reuse;
kernel endpoint evidence must be checked independently. Unlearned connections
remain outside coverage. No request bytes, call results or errno are changed.

The outer diagnostic reads namespace links to identify the real target tasks,
records their original status/NSpid and uses actual outer TGIDs for Binder proc
files, as required by this exact kernel's current->tgid naming. It mounts debugfs
only in the temporary diagnostic environment with nosuid,nodev,noexec. Each
selected Binder file is capped at 256 KiB and errors/EOF are recorded. Complete
043 inner maps and original samplers remain unchanged.

ASan/UBSan parser fixtures cover tokenless association, fd/handle isolation and
immutable payloads. Static workflow checks constrain all changes to the declared
observation. These tests are not original service or desktop acceptance evidence.

Keep the standard Ubuntu default, original manual entry, original images,
enabled/active screen-off timer, authentic identities and policy/audit evidence.
SELinux permissive remains authorized, not disabled. Retain only the latest two
experimental entries, archiving old contents/hashes outside ESP first; do not
remove shared payloads. All logs and artifacts use exclusive unique filenames.

All three pinned reference projects remain part of the actual service and
graphics integration route. Actual desktop pixels and interaction, not observed
transaction submission, are the completion criterion. Runtime and preservation
results will be recorded separately without overwriting this candidate statement.

# Commercial 043: original Binder boundary observation

Desktop acceptance remains pending. This candidate has not yet supplied runtime
evidence. It continues the original account, Ability Manager, SceneBoard,
RenderService and composer path; it does not substitute a desktop or inject roots.

042 closure and the exact original library audit identify a preload observation
blind spot caused by SYMBOLIC binding and internal dispatch. 043 therefore adds
read-only observation at the original IPC library's external ioctl boundary.
Only exact original RenderServiceConnection and RenderService interface tokens
are logged. Command parsing, record counts and logging rates are bounded. The
original ioctl runs once, with original buffers, return value and errno retained.
Kernel consumption is not proof of service execution or rendered presentation.
Missing records likewise do not prove missing transactions.

The original single-read process maps are replaced by bounded, EOF-aware reads.
Selected existing samples also capture the real kernel Binder transaction ring
and matching process state, if available. Debugfs is mounted only inside the
isolated target, with nosuid,nodev,noexec. Failures are recorded, not hidden.

Host parser fixtures pass ASan and UBSan. Workflow checks retain the original
outer runtime, normal application launch and 150/270-second target/outer bounds.
The ordered 001/017/016/043 overlay chain matches the complete 043 initrd.
No original image, authentication, sandbox or token check is modified. SELinux
remains supported with authorized permissive diagnostics, not disabled.

Installation and one-shot execution retain the standard Ubuntu default and
original manual entry, verify the enabled/active screen-off timer, and preserve
numbered evidence. Only the latest two experimental entry files are retained;
older entry contents and hashes must be archived outside the ESP before removal.
Shared payloads are not removed. Runtime and post-return results are recorded
separately under reports/commercial61-native-043 without rewriting this statement.

All three references remain applicable: L410 HarmonyOS Adaptations for the
graphics namespace, HarmonyMac for original service/NativeWindow integration,
and L410 Linux Compatibility Platform for later AnCo integration, not a desktop
replacement. The acceptance criterion is actual original desktop pixels and
interaction, not a service, parser or transaction microtest.
